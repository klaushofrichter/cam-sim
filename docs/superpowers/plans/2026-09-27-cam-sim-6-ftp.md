# cam-sim Plan 6: FTP upload

**Goal:** like the RLC-1224A, cam-sim uploads each finished recording to an FTP
or FTPS server, so the camera gateway's clip intake can be built and tested
against it.

**Spec:** `docs/superpowers/specs/2026-09-26-cam-sim-design.md` §11.3.

## What the camera does (measured 2026-09-26/27)

- It is an FTP **client** only; `SetFtpV20` configures it. Partial writes reset
  keys, and `server: ""` answers `-4`.
- **Uploads:**
  - named `<remoteDir>/YYYY/MM/DD/<Name>_00_YYYYMMDDHHMMSS.mp4` (with
    `autoDir: 1`), with the start time in camera-local time;
  - plus `<same stem>.jpg`, a full-resolution picture;
  - main stream by default; `streamType: 1` selects sub; the `moov` atom
    comes first;
  - FTPS only by default (`onlyFtps: 1`), plain FTP with `onlyFtps: 0`;
  - no trigger information in the names.
- **`TestFtp {Ftp: <whole object>}`:**
  - it tests without saving anything;
  - a partial object answers `-56 "err get data from json"`;
  - an unreachable server answers `-454 "ftp connect failed"`;
  - success: `{rspCode: 200}` (assumed; not reachable from here).

## Decisions

- `src/ftp/uploader.ts`: on each finished recording (`Events` emits
  `recording`), when `Ftp.enable === 1` and `Ftp.schedule` allows one of the
  recording's trigger types at its start hour, upload the clip (fixture MP4 of
  the chosen stream) and the snapshot JPEG with `basic-ftp`.
  - FTPS: explicit TLS, certificate not verified, as the camera doesn't.
  - One upload at a time, in a queue.
  - A failure is logged, counted and dropped. The camera doesn't retry
    (unverified), so neither do we.
- Counters `ftpUploads`, `ftpFailures` and `ftpDropped` (at most 20 wait), and
  the event `ftp` on the SSE feed (`{file, ok, error?}`).
- Faults `ftp.fail` (every upload and `TestFtp` fails with `-454`) and
  `ftp.delayMs`.
- `TestFtp`:
  - a whole object is required: a missing `server`, `port`, `userName`,
    `password` or `remoteDir` key answers `-56`;
  - it connects and logs in, then answers `{rspCode: 200}` or `-454`. It
    doesn't check `remoteDir`: uploads create it as needed;
  - it never changes the settings.
- `CAMSIM_FTP_SERVER`, `_PORT`, `_USER`, `_PASSWORD(_FILE)`, `_DIR`, `_TLS`
  (`true` = `onlyFtps: 1`) and `_STREAM` (`main` or `sub`) set and enable FTP
  at start. This is for compose and the gateway's tests.
- Tests against an in-process `ftp-srv` server, plain and with TLS.
